# Shared Play listener files

The browser library uses IndexedDB (`spectralis-local-audio`), with separate metadata and Blob stores. Importing and removing files does not contact the backend. Files belong to the current browser/site, survive reload and sign-out, and disappear when site data is cleared. Imports are deduplicated by SHA-256. The limit is 64 MiB per file and 512 MiB per browser library.

Adding a file to a room requires a server-verified Ward identity and room admission. A host session key alone does not qualify. Development and staging keep Ward disabled, so they support local importing and listening but reject uploads. `GET /shared-play/v2/config` exposes `accountsEnabled` without starting sign-in.

`audioUploads` is an independent boolean room capability, defaulting to true. It is separate from link requests (`queueAdd`). Hosts persist the setting locally, send `roomCapabilities` with session creation, and change it through authenticated `caps.set` messages. Both the manifest and socket report the current value.

All upload endpoints are below `/shared-play/v2/sessions/{code}`:

| Request | Purpose |
| --- | --- |
| `POST /uploads` | Multipart `file`, optional `title`. Requires an admitted account and enabled uploads; returns `{item, queue}`. |
| `GET /uploads/{id}/audio/{filename}` | Original file; requires the room's host key, never a token in the URL. |
| `POST /uploads/{id}/received` | Host acknowledgment after saving and queueing a local copy. Deletes the server original; retries are idempotent. |
| `DELETE /queue/items/{id}` | Host removes one request atomically, including any pending upload. |

Accepted extensions are MP3, M4A, WAV, FLAC, Ogg, Opus, AAC and AIFF, with corresponding file signatures checked before storage. The host's audio engine decodes the actual track. Each account may have five files awaiting host receipt; the room may hold 256 MiB of pending files and 100 requests. Upload IDs, source URLs and attribution are generated by the backend, not trusted from link requests.

The host uses `SharedPlayListenerUploads`, which validates the URL against the room and backend, bounds download size/time, atomically saves the file, then queues and acknowledges it. Failed receipt retries do not enqueue twice. Pending files are kept under the app's known temporary directory with an active lease; the existing temporary-file collector removes stale copies after two days.

Server originals expire after one hour if unreceived, and are also deleted on receipt, queue removal or room end. A one-minute collector uses durable cleanup records without Redis TTLs so object-store audio can be removed after its session keys expire. Playback packages live only for the session and are collected on room end/expiry. No permanent account audio library is created on the server. Storage deletion failures retain cleanup records for retry.

- `cargo test --manifest-path backend/Cargo.toml uploads::tests -- --test-threads=1`
- `dotnet test Spectralis.Tests/Spectralis.Tests.csproj --filter "FullyQualifiedName~SharedPlay"`
- `python web-share/tests/room_upload_backend_test.py` after `cargo build --manifest-path backend/Cargo.toml` (real local backend, isolated Ward stub and Chromium; no live account)
- `python web-share/tests/room_browser_test.py`

The public Player repo uses the same IndexedDB implementation at `public/local-library.js`; keep that copy identical to `web-share/local-library.js` when changing the storage format.
